# Статус проекта

Дата проверки: 4 июня 2026.

## Сейчас готово

- Техническая основа: Next.js App Router, React, TypeScript, Tailwind, shadcn/radix, Prisma, PostgreSQL и Redis через Docker Compose.
- Авторизация: регистрация, вход, выход, хеширование паролей, cookie сессии, хранение сессий в Redis.
- Защита маршрутов: `/profile` и `/recipes/[recipeId]/edit` закрыты от неавторизованных пользователей на уровне proxy.
- База данных: модели пользователя, рецепта, КБЖУ, ингредиентов, групп ингредиентов, единиц измерения, оборудования, шагов, комментариев и корзины.
- Рецепты: главная страница со списком рецептов из БД, страница просмотра рецепта, метаданные страницы рецепта, заготовка страницы редактирования с проверкой владельца.
- Страница рецепта: hero, описание, автор, КБЖУ, выход рецепта, порции, группы ингредиентов, оборудование, шаги с изображениями, комментарии.
- Ингредиенты: справочник ингредиентов, стикеры, карточка ингредиента, ссылка на рецепт для подготовленных ингредиентов.
- Работа с количеством: пересчет ингредиентов при изменении выхода рецепта, округление единиц измерения, поддержка порций.
- Корзина/список покупок: добавление одного ингредиента или всех ингредиентов рецепта, удаление позиций, группировка по рецептам и общий объединенный список.
- Хранение корзины: для гостей используется браузерное хранилище, для авторизованных пользователей корзина сохраняется в БД.
- UI: header с логотипом, поисковой строкой, действиями авторизации и индикатором корзины.
- Дизайн: HTML-артефакты для страницы рецепта, страницы входа, дизайн-системы и вариантов ingredient line; есть скрипт синхронизации с Open Design.
- Проверки: `npm run lint` и `npm run build` проходят на 4 июня 2026.

## Важные расхождения

- В MVP-документах описана приватная база рецептов, но текущие `/` и `/recipes/[recipeId]` доступны без проверки владельца. Нужно выбрать направление: private-first MVP или публичная витрина с явной моделью видимости.
- Создание, полноценное редактирование и удаление рецептов пока не реализованы. Страница редактирования сейчас является заглушкой.
- Личного списка рецептов пользователя пока нет. Главная страница показывает общий список рецептов из БД.
- Поиск в header пока является только UI-полем без фильтрации и серверной логики.
- Тестовый стек не подключен. Сейчас проверяются lint и production build.
- `README.md` остается стандартным шаблоном Next.js и не описывает фактический запуск проекта.
- Компонентная документация отстает от новых ingredient/sidebar/cart компонентов.

## Ближайшие задачи

1. Зафиксировать продуктовую модель доступа к рецептам: приватная база для MVP или публичная витрина с полем видимости.
2. Если MVP остается приватным, закрыть список и просмотр рецептов проверкой владельца; если выбран публичный сценарий, добавить явную модель `visibility`.
3. Реализовать личный список рецептов пользователя и связать его с профилем.
4. Реализовать создание рецепта под текущую схему: выход, порции, группы ингредиентов, единицы измерения, шаги, оборудование, КБЖУ.
5. Заменить заглушку редактирования на полноценную форму и добавить server action обновления.
6. Добавить физическое удаление рецепта с подтверждением и проверкой владельца.
7. Подключить минимальный тестовый стек и покрыть auth, доступ к рецептам, пересчет ингредиентов и корзину.
8. Актуализировать `README.md` и компонентную документацию.
